# 专题答题模板

## 质量属性

六要素：刺激源、刺激、环境、制品、响应、响应度量。

| 属性 | 识别词 | 常用策略 |
|---|---|---|
| 性能 | 响应时间、吞吐量、并发、延迟 | 缓存、并发处理、资源池、负载均衡、减少通信 |
| 可用性 | 故障恢复、自动切换、不中断 | 心跳、Ping/Echo、冗余、故障检测、选举、降级 |
| 安全性 | 加密、认证、授权、审计、不可抵赖 | 身份认证、访问控制、加密、签名、日志审计 |
| 可修改性 | 快速变更、插件化、扩展 | 抽象、封装、低耦合、高内聚、配置化 |
| 可测试性 | 自动化测试、可观测、故障注入 | 接口隔离、依赖注入、日志、监控、测试桩 |
| 互操作性 | 跨系统、异构平台、标准协议 | 标准接口、适配器、消息协议、数据格式转换 |

回答质量属性题时，先写属性判断，再写题干证据，最后写场景六要素或设计策略。

## Redis 与缓存

答题关键：

- Cache Aside 读流程：先查缓存，未命中查数据库，再写入缓存并设置过期时间。
- 写流程优先答：先更新数据库，再删除缓存；删除失败用异步重试或监听 binlog 补偿。
- 延时双删用于降低并发读写导致旧值回填缓存的概率。
- 缓存穿透：缓存空值、布隆过滤器、参数校验。
- 缓存击穿：互斥锁、逻辑过期、热点预热。
- 缓存雪崩：过期时间随机化、多级缓存、限流降级、集群高可用。
- Redis 集群：主从复制、哨兵、Cluster 分片；分别说明高可用、故障转移、水平扩展。

## 分布式事务

按一致性要求选择方案：

| 场景 | 方案 | 答题要点 |
|---|---|---|
| 强一致、参与方少 | 2PC/3PC | 协调者、准备、提交、阻塞和性能代价 |
| 业务可拆补偿 | Saga | 正向事务、补偿事务、最终一致 |
| 需要资源预留 | TCC | Try、Confirm、Cancel，幂等和悬挂处理 |
| 异步解耦 | 本地消息表/可靠消息 | 本地事务写业务和消息，投递、确认、重试 |

必写幂等、超时、重试、补偿、对账、监控告警。

## 微服务治理

注册发现题：

- 注册中心集群部署，避免单点故障。
- 服务实例心跳和健康检查，及时剔除异常节点。
- 客户端或网关缓存服务列表，并设置刷新和失败重试策略。
- 调用链路设置超时、重试、限流、熔断和降级。
- 用监控、日志、链路追踪定位故障。

熔断限流题：

- 熔断：失败率、异常数或响应时间超过阈值后打开，快速失败或 fallback。
- 降级：关闭非核心功能、返回默认值、异步处理，保护核心链路。
- 限流：固定窗口、滑动窗口、漏桶、令牌桶；热点参数可单独限流。
- 隔离：线程池隔离、舱壁隔离、资源池隔离。

## 负载均衡

先判断普通轮询是否合理：节点能力差异大、请求耗时差异大、健康状态变化频繁时，不宜只用轮询。

可答策略：

- 基于权重、最小连接数、响应时间或一致性哈希选择实例。
- 加健康检查，把异常节点移出负载池。
- 用网关、Nginx、Ingress 或客户端负载均衡适配不同层级。
- 结合 Kubernetes HPA、弹性扩缩容、灰度发布提升稳定性。

## 云原生

答题结构：

- 容器化封装应用和依赖，提升环境一致性。
- Kubernetes 负责编排、服务发现、弹性伸缩、滚动发布和故障自愈。
- CI/CD 支持自动构建、测试、部署和回滚。
- 可观测性覆盖日志、指标、链路追踪和告警。
- 配置中心、密钥管理和镜像仓库保障配置与安全。

## 大数据

常见架构：

- Lambda：批处理层 + 速度层 + 服务层；兼顾历史准确性和实时性，但系统复杂。
- Kappa：以流处理为核心，重放日志修正数据；架构简化，但依赖流平台和数据重放能力。
- 数据湖/湖仓：统一存储结构化和非结构化数据，配合元数据、权限和治理。

答题时绑定数据量、时效性、准确性、成本和运维复杂度。

## UML 与建模

- 用例图：识别参与者、用例、包含、扩展、泛化。
- 类图：实体类、边界类、控制类；关系包括关联、聚合、组合、继承、依赖。
- 顺序图：对象生命线、消息顺序、同步/异步调用。
- 状态图：状态、事件、迁移、守卫条件、动作。

建模题优先从名词找类，从动词找操作，从流程找消息，从状态词找状态。

## 安全与权限

认证授权：

- SSO 用于统一登录，OAuth2/OpenID Connect 用于授权和身份声明，JWT 可承载身份与权限声明。
- RBAC 适合角色稳定、功能权限清晰的系统。
- ABAC 适合按部门、岗位、时间、数据敏感级别等条件做细粒度控制。
- 金融和敏感数据场景可用 RBAC + ABAC 混合模型。

旧 Token 风险：

- 原因：JWT 无状态，权限变更后旧令牌仍可能通过本地校验。
- 措施：短有效期、Refresh Token、黑名单、权限版本号、集中校验、高风险操作二次认证。

加密审计：

- 传输用 TLS，存储用对称加密，密钥用 KMS/HSM 管理。
- 审计日志记录主体、客体、操作、时间、来源、结果和权限变更前后值。

## 领域架构 DSSA

答题要点：

- 识别领域共性需求和变化点，建立领域模型。
- 抽取参考架构、公共构件、接口规范和约束规则。
- 针对具体项目裁剪参考架构，复用领域构件。
- 优点是复用、质量稳定、降低成本；代价是前期领域分析成本高。
