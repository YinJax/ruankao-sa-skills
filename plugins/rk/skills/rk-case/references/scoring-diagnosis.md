# 训练评分与诊断

## 评分口径

这是非官方训练评分，只用于复习校准。官方阅卷可能受题目标准答案、地区执行、当年难度和阅卷尺度影响。

若用户未提供分值，按 75 分估算：

| 维度 | 权重 | 观察点 |
|---|---:|---|
| 审题与覆盖 | 25% | 是否逐问作答，是否回应题目动词和限定条件 |
| 题干证据 | 20% | 是否引用故障、目标、约束、现有技术栈 |
| 知识点准确 | 25% | 概念、机制、适用场景、优缺点是否准确 |
| 落地措施 | 20% | 是否给组件、流程、策略、监控、异常处理 |
| 表达与得分效率 | 10% | 是否分点清晰、关键词密集、无空泛口号 |

## 每问估分

按每问给出：

```text
问题N：估分 x/y，置信度：高/中/低
已覆盖：...
主要丢分：...
建议补充：...
改写示例：...
```

## 常见丢分类型

- `答非所问`：题目问风险，答案只写定义；题目问设计，答案只写概念。
- `没有题干证据`：技术名词正确，但没有说明为什么适合本案例。
- `措施不闭环`：只写限流、熔断、缓存，没有写监控、告警、降级或补偿。
- `绝对化`：把最终一致写成强一致，把某产品写成唯一方案。
- `粒度错误`：问架构方案却只写代码细节，或问算法却只写业务目标。
- `模板腔`：大量“提高系统性能、增强可靠性”，缺少具体手段。

## 评分点套路库

| 问法 | 得分点形态 | 答题句式 |
|---|---|---|
| 说明/简述 | 概念 + 场景作用 + 后果 | X 是...，在本题中用于...，可以解决/避免... |
| 分析原因 | 现象 + 根因 + 题干证据 | 出现 A 的原因是 B，题干中的 C 说明... |
| 提出措施 | 组件/流程/策略 + 异常处理 + 验证 | 可采用 X，并通过 Y 处理异常，最后用 Z 验证效果 |
| 比较/是否合理 | 结论 + 条件 + 代价 | 在...条件下合理/不合理，因为...，代价是... |
| 补图/补表 | 上下游关系 + 术语归位 | 根据 A 到 B 的流向，应补 C |

诊断答案时，先判断漏的是哪类评分点，不要只说「不完整」。

## 改进优先级

1. 先补漏问。没有回答的问题优先级最高。
2. 再补题干绑定。每个要点至少绑定一个现象或约束。
3. 再补机制链路。写清输入、处理、输出、异常路径。
4. 最后压缩表达。把长段落改成得分点列表。

## 估分保守规则

- 缺题干或缺用户答案时，只给区间分，不给精确分。
- 参考答案未知时，按知识点覆盖估分，并声明置信度中或低。
- 用户答案包含明显错误概念时，先扣准确性分，再看是否有可得的场景分。
- 不因措辞漂亮加分；案例分析主要看要点覆盖。
