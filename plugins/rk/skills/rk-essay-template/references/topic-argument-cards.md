# 专题论点卡

Use this reference when a paper template needs ready-to-expand theory cards. The source pattern comes from classified classroom notes: keep the structure and exam focus, but do not copy long source wording.

## 使用规则

- 先按题干选择 1 个主专题，最多 1 个辅助专题。
- 每篇模板选 3 张论点卡；少于 3 张能被项目事实支撑时，先补访谈问题。
- 每张卡都要落到用户项目事实：约束、架构师动作、取舍和结果。
- 缺少项目证据时写 `[待本人确认]`，不要补造指标、评审过程或技术栈。

## 架构评估 / ATAM

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| 架构评估要围绕质量属性场景，而不是只看技术栈 | 评估目标、质量属性、场景、风险点、敏感点和权衡点 | 性能、可靠性、安全、可维护性等真实约束 |
| ATAM 适合发现架构方案中的权衡和风险 | 场景收集、架构描述、属性分析、风险识别、结果报告 | 评审会、备选方案比较、风险清单、改进措施 |
| 评估结果必须反哺架构决策 | 评估不是总结，而是支持取舍和演进 | 缓存、拆分、冗余、降级、监控、数据一致性等调整 |

常见风险：把评估写成上线总结；只说“满足性能要求”，不写场景和验证。

## 数据访问层设计

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| 数据访问层的价值是隔离业务逻辑和数据源变化 | DAO、DTO、ORM、离线数据模型、统一访问接口 | 多库、多源、接口数据、本地缓存或离线数据 |
| 访问模式要按一致性、性能和维护成本选择 | 在线访问、批量同步、对象关系映射、数据传输对象 | 查询热点、事务边界、同步频率、数据口径 |
| 数据访问设计必须包含异常和校验闭环 | 事务、重试、幂等、数据校验、错误回滚 | 导入失败、脏数据、网络异常、版本冲突 |

常见风险：只罗列 ORM/DAO 名词；没有说明为什么这样分层和如何验证数据正确。

## 云原生架构

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| 云原生不是“上云”，而是面向弹性和快速交付设计 | 容器化、微服务、持续交付、弹性、可观测 | 部署环境、扩缩容、发布流程、资源隔离 |
| 可观测性是云原生系统可运维的前提 | 日志、指标、链路追踪、告警、容量监控 | 故障定位、性能瓶颈、用户访问异常 |
| 自动化部署要和安全、成本、稳定性一起权衡 | CI/CD、镜像、配置、灰度、回滚 | 发布频率、环境一致性、回滚策略、资源成本 |

常见风险：只写用了云服务器或 Docker；没有弹性、自动化和可观测机制。

## SOA / 微服务

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| 服务拆分要围绕业务边界和变化频率 | 服务识别、粗粒度、松耦合、接口契约 | 业务域、模块职责、接口边界、团队协作 |
| 服务治理解决的是调用失控和演进困难 | 注册发现、契约、限流、熔断、监控、版本管理 | 接口稳定性、调用链、故障隔离、灰度发布 |
| SOA/微服务要说明代价，不宜硬套 | 分布式复杂度、数据一致性、运维成本 | 普通分层系统、单体演进、拆分收益与成本 |

常见风险：把普通接口调用写成微服务；只写拆分，不写治理和代价。

## 安全架构

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| 安全架构要从威胁和资产边界出发 | 身份认证、访问控制、审计、加密、防护检测响应 | 用户角色、敏感数据、权限边界、合规要求 |
| WPDRRC 强调安全闭环而非单点工具 | 预警、防护、检测、响应、恢复、反击 | 日志审计、告警、备份恢复、应急流程 |
| 安全设计需要平衡可用性和管理成本 | 最小权限、分级授权、加密开销、审计粒度 | 登录、权限、数据传输、操作留痕 |

常见风险：堆安全产品；没有威胁场景、控制点和验证方式。

## Lambda / Kappa 大数据架构

| 论点 | 理论依据 | 项目落点 |
| --- | --- | --- |
| Lambda 适合同时需要历史全量和实时增量的场景 | 批处理层、加速层、服务层 | 离线统计、实时看板、历史回溯 |
| Kappa 通过流式链路降低复杂度，但历史处理能力有边界 | 实时层、服务层、日志重放、统一口径 | 实时计算、算法回放、消息队列、数据湖 |
| 架构选择取决于数据规模、实时性和维护成本 | 复杂度、计算开销、历史数据能力、成本预算 | 数据量、延迟要求、团队维护能力 |

常见风险：背层次结构；没有解释为什么选 Lambda、Kappa 或折中方案。
