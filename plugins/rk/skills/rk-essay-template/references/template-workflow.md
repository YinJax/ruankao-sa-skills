# 模板工作流

1. 分材料：区分项目事实、题目材料和范文材料。
2. 拆题目：找出题干要求、选题方向、限制词和必须覆盖的知识点。
3. 访谈事实：只补模板需要的关键事实，不扩散到无关细节。
4. 建事实卡：把可辩护事实、待确认事实和风险分开。
5. 配模板：把事实映射到摘要、背景、理论、应用、总结五部分。
6. 检查覆盖：确认每个题干义务都能在模板里找到落点。

## 事实卡字段

- 项目时间：开始、上线、验收或关键阶段；用户要求近三年项目时，以用户提供的考试年份或日期为校验基准。
- 项目背景：业务痛点、建设目标、干系人、工期和投入。
- 个人角色：架构师职责、参与深度、主导动作。
- 系统构成：核心功能、关键模块、外部系统、数据流。
- 主题素材：与题目相关的约束、决策、实施、权衡、结果。

## 生成原则

- 先适配题目，再套项目事实。
- 先保真，再追求完整。
- 不能支撑题目的项目，不硬造模板。
- 范文只能提供写作结构和论点路径，不能提供用户项目事实。

## 质量门

生成前确认：

- 摘要能说明项目时间、背景、目标、角色、技术要点和结果。
- 正文背景能交代项目基本信息、系统构成和团队角色。
- 理论部分至少有 3 个题目相关模块。
- 项目应用部分能说明理论如何落到真实场景。
- 总结同时包含正面效果和不足改进。
