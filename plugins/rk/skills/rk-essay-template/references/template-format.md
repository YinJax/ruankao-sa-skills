# 模板格式

Use this reference when the user already gives the摘要模式、正文框架或段落字数要求。

## 默认格式

默认使用用户给出的考场框架；如果用户提供其它格式或真题要求，以用户格式为准。

### 摘要

- 项目介绍：时间、背景、目标、个人角色，约 100 字
- 技术要点：约 150 字
- 达成效果：约 50 字

### 正文

1. 背景介绍，约 500 字
2. 论文题目相关知识点理论，约 1500 字
3. 项目实例说明理论应用，约 300 字
4. 总结，约 200 字

## 理论展开写法

理论展开不是堆教材定义。先按题目拆成 3 个核心模块，再把每个模块写成“理论定位 + 项目落点”的可替换段。

推荐结构：

1. 模块一：概念边界、适用场景、项目中的问题。
2. 模块二：关键方法、架构决策、实施动作。
3. 模块三：风险控制、权衡取舍、验证结果。

严格按用户“理论 1500 字 + 项目应用 300 字”要求时，项目落点可以在理论段中轻触，在项目应用段集中展开。用户要求范文式写法时，可以让每个模块内部完成“理论 -> 场景 -> 动作 -> 结果”。

## 考场替换卡

模板结尾输出一张简短替换卡：

- `题目关键词替换位`
- `知识点模块替换位`
- `项目事实替换位`
- `结果数据替换位`
- `不能照搬的位置`

## 文档导出格式

用户要求导出 Word、docx、文档或保存到文件时，文档至少包含：

1. 论文模板正文
2. 考场替换卡
3. 待确认清单
4. 质量检查
5. 下一步：建议用 `/rk-essay` 诊断

聊天回复只保留文件路径、核心结论、替换卡摘要和下一步建议。

## 写法规则

- 每一段都保留可替换位。
- 只写用户给出的事实，不补造项目数据。
- 结果写观察到的变化，不写空泛结论。
- 需要保留题目适配位，例如 `[题目关键词对应的核心机制]`、`[项目中的真实案例]`。
