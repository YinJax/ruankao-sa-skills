# 考前押题路由

用于 `rk-essay-final` 把押题主题映射到“企业数字化底座平台”项目素材。

## 强适配

| 方向 | 推荐论点卡 |
| --- | --- |
| 微服务 / SOA / 面向服务 | 服务边界识别；接口契约与服务治理；独立部署与弹性伸缩 |
| 云原生 / CloudOps | 容器化与自动化部署；弹性伸缩与高可用；可观测与告警 |
| 系统测试 / 性能测试 | 质量目标与测试策略；自动化与AI辅助用例；压测瓶颈定位与调优 |
| 企业集成 / 多源异构数据集成 | 身份与组织主数据统一；流程与消息集成；模型映射与质量校验 |
| 安全架构 | 统一认证；分级授权与数据权限；审计与敏感数据保护 |
| 设计模式 / DDD / 分层设计 | 限界上下文；聚合与领域事件；适配器/策略/组合模式 |

## 可写但要补角度

| 方向 | 写法 |
| --- | --- |
| 分布式事务 | 写“可靠消息 + 幂等 + 补偿 + 对账”，落到流程集成和存量系统同步 |
| 负载均衡 | 写网关入口、服务发现健康检查、HPA扩缩容和故障切换 |
| 软件维护 | 写可维护性设计、适配器演进、缺陷修复、持续迭代 |
| 模型驱动架构 | 写统一建模、动态建表、模型发布、存量模型适配 |
| 软件可靠性评价 | 写可用性目标、故障场景、测试和监控证据；缺少真实统计时标 `[待确认]` |

## 弱适配

| 方向 | 处理 |
| --- | --- |
| Serverless | 不建议硬套；除非改写成云原生弹性与事件触发的弱相关题 |
| 秒杀 | 不建议硬套；该项目没有典型高并发交易库存场景 |
| 边缘计算 | 不建议硬套；该项目缺少边端设备、低时延、本地计算事实 |
| 大数据 Lambda | 勉强可写；需要补批流数据链路，否则转多源数据集成 |

## 固定项目事实

- 2025年1月启动，2025年12月核心能力上线，历时11个月。
- 接入 PLM、项目管理、财务、OA 四个存量系统。
- 团队包含需求3人、后端8人、前端4人、测试3人。
- 平台包含认证、权限、流程、消息、建模、编码、上下文治理等服务。
- 技术栈可用事实：API网关、JWT、微服务、Kubernetes、Redis、RabbitMQ、Prometheus、Grafana、ELK/Loki、JMeter、JUnit、Playwright。
- 结果数据优先使用文档已有说法：新应用接入从数月缩短至2-3周；500并发平均响应300ms以内；P99 800ms以内；故障定位缩短至分钟级；测试覆盖率约90%以上。

## 禁写提醒

- 不要把普通部署写成 Serverless。
- 不要把平台管理系统硬写成秒杀交易系统。
- 不要把 AI 写成所有题目的主线。
- 不要只有技术名词，必须写本人决策和取舍。
