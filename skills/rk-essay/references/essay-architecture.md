# 通用论文骨架

Use the skeleton as a memory aid. Adapt the brackets to the prompt and project facts; do not preserve fixed wording across essays.

## 1. 摘要

- State the topic, project type, role, core architecture decision, two or three key issues, and outcome.
- Aim for a compact preview of the whole answer, not a definition of the topic.

## 2. 项目背景与本人职责

- Explain business goal, users, scale, constraints, lifecycle stage, and why the topic mattered.
- State the user's actual role and responsibilities. Add only facts the user can defend in follow-up questions.

## 3. 题干要点展开

For each required point, use this chain:

`场景/约束 -> 架构决策 -> 实施方式 -> 遇到的问题 -> 权衡或改进 -> 验证结果`

Make the topic-specific section visible with numbered subheadings that mirror the prompt. Connect technical choices to quality attributes such as performance, availability, security, modifiability, scalability, or data consistency.

## 4. 成效、反思与结尾

- State observable results, remaining limitations, and the next improvement.
- Conclude by returning to the prompt's topic and the project value.

## Paragraph Check

Before keeping a paragraph, confirm it contributes to a prompt obligation, a project fact, a decision rationale, or an evidence-backed result. Replace pure textbook exposition with a project-linked explanation.

## Exam-Like Shape Check

Before substantial rewrite, check the draft against `essay-sample-patterns.md`:

- 摘要是否同时给出题目、项目、角色、核心措施和结果。
- 正文是否是 3 个左右的题目相关论点，而不是技术清单。
- 每个论点是否包含本人动作、方案权衡和可观察结果。
- 结尾是否回扣题目，并承认一个真实不足或后续改进。
