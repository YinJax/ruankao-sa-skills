# 范文结构模式

Use this reference when the user supplies sample essays, template PDFs, or asks for an exam-ready writing template.

The `system_architect` essay folders include current sample references, a set of true-prompt sample essays, older sample essays, and exam technique/template material. Use them only to infer structure and quality checks. Do not copy sample wording, project facts, titles, or paragraphs.

## 可吸收内容

| 来源类型 | 可吸收 | 不可吸收 |
| --- | --- | --- |
| 真题范文 | 题目分类、段落比例、论点数量、项目落点方式 | 原文句子、项目名称、指标、个人经历 |
| 参考范文 | 主题覆盖、理论点组织、常见应用角度 | 范文事实、作者视角、固定套话 |
| 应试技巧与模板 | 摘要要素、正文层次、结尾检查项 | 万能开头、万能结尾、承诺通过 |

## 生成时的结构质量门

1. 摘要：项目背景、本人角色、题目主题、2-3 个措施、结果都要出现。
2. 背景：不超过正文主篇幅的 25%，避免把论文写成项目介绍。
3. 理论展开：选择 3 个与题目直接相关的论点，不堆 5 个以上技术名词。
4. 项目应用：每个论点按 `场景 -> 决策 -> 实施 -> 权衡 -> 结果` 展开。
5. 总结：回扣题目，写一个可辩护的效果和一个真实不足。

## 反范文味检查

- 删除只解释教材概念、没有项目动作的段落。
- 删除“显著提高、极大改善、圆满完成”等无证据形容。
- 把团队泛称改成用户真实角色下的动作。
- 把范文里的通用案例换成用户自己的项目事实；缺事实则写 `[待本人确认]`。
